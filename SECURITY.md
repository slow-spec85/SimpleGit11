# Security Policy

## Supported versions

Until SimpleGit11 reaches a stable 1.0 release, security updates are provided
for the latest published preview or release candidate only. After 1.0, the
latest stable release is supported unless its release notes state otherwise.

Older releases and development builds from source are not supported with
security updates.

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's private
vulnerability reporting feature:

1. Open the **Security** tab of the SimpleGit11 repository.
2. Select **Advisories** and then **Report a vulnerability**.
3. Include the affected version, impact, reproduction steps, and any suggested
   mitigation.

Do not open a public issue or discussion for an undisclosed vulnerability. If
private vulnerability reporting is unavailable, contact the repository owner
through the contact method listed on their GitHub profile and ask for a private
reporting channel without including vulnerability details in the first message.

Reports may be submitted in English or Russian. When attaching logs from
`%LOCALAPPDATA%\SimpleGit11\Logs`, remove access tokens, credentials, repository
URLs, user names, local paths, and other personal or confidential information.

## What to expect

The maintainers aim to acknowledge a report within three business days and
provide an initial assessment within seven business days. Resolution time
depends on severity and complexity.

The maintainers will coordinate disclosure with the reporter. Please avoid
public disclosure until a fix or mitigation is available. Reporter credit will
be included in the advisory when requested and appropriate.

## Scope

This policy covers vulnerabilities in SimpleGit11 itself and in the release
artifacts published by the project. Vulnerabilities in third-party components
should also be reported to the corresponding upstream project. See
[THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt) for dependency notices.
