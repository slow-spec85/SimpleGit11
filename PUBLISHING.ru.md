# Сборка, установка и обновление SimpleGit11

## Готовый дистрибутив

SimpleGit11 распространяется как **unpackaged, self-contained, win-x64** приложение:

- MSIX и Microsoft Store не используются;
- .NET и Windows App SDK включены в дистрибутив;
- приложение не требует установки сертификата или прав администратора;
- для работы нужна вся папка приложения, а не только `SimpleGit11.exe`.

Для каждой опубликованной версии в разделе Releases доступны:

```text
SimpleGit11-<version>-win-x64-en-US.msi
SimpleGit11-<version>-win-x64-en-US.msi.sha256
SimpleGit11-<version>-win-x64-ru-RU.msi
SimpleGit11-<version>-win-x64-ru-RU.msi.sha256
```

Автоматически создаваемые GitHub архивы `Source code (zip)` и `Source code (tar.gz)` содержат исходный код, но не готовое приложение.

## Системные требования

Для готового приложения:

- Windows 11 x64;
- Git for Windows.

Для сборки из исходного кода дополнительно потребуются:

- .NET SDK 10 (минимум 10.0.100; более новые feature band и patch-версии 10.0 разрешены);
- Windows SDK с поддержкой Windows 10, версия 19041 или новее;
- доступ к NuGet для восстановления зависимостей.

## Установка

### MSI с выбором SSH

Выберите `SimpleGit11-<version>-win-x64-ru-RU.msi`
(или `en-US`). Выберите установку для текущего пользователя (по умолчанию,
`%LOCALAPPDATA%\Programs\SimpleGit11`) или для всех пользователей
(`%ProgramFiles%\SimpleGit11`, с подтверждением администратора).
На следующем шаге можно изменить папку установки.
На странице компонентов можно включить **Поддержку SSH** и ярлык рабочего стола;
по умолчанию они выключены. Основное приложение обязательно.
Git не входит в пакет: для локальной работы установите его отдельно, для SSH
он должен быть установлен на удалённой машине.

Повторно откройте исходный MSI для изменения компонентов, восстановления или удаления.
Предварительно закройте SimpleGit11. Обновление сохраняет область установки,
выбранную папку, выбор SSH и настройки. Для смены области или переноса папки
существующую установку сначала нужно удалить.
Не устанавливайте MSI поверх вручную распакованной portable-копии.

При полном удалении установки текущего пользователя появится флажок **Также удалить все настройки и данные SimpleGit11**,
по умолчанию выключенный. Он удаляет `%LOCALAPPDATA%\SimpleGit11`: настройки,
SSH-профили, историю, журналы и вложенные папки. Сначала сохраните нужные данные.
Репозитории и SSH-ключи вне этой папки не затрагиваются; данные внутри удаляются целиком.
По ссылкам/junction-каталогам переход не выполняется — они и содержащие их папки
могут остаться. Профили других пользователей не очищаются. Из каталога программы
удаляются только файлы MSI; чужие плагины остаются. Обновление, восстановление
и удаление только SSH-компонента никогда не очищают настройки. При удалении
установки для всех пользователей личные данные всех профилей сохраняются;
флажок очистки не показывается, параметр `PURGEUSERDATA=1` также не удаляет их.

## Проверка SHA-256

Поместите MSI и соответствующий `.sha256` в один каталог, затем выполните в PowerShell:

```powershell
$installerPath = ".\SimpleGit11-1.0.0-win-x64-ru-RU.msi"
$checksum = "$installerPath.sha256"

$expected = (Get-Content $checksum).Split(
    " ",
    [System.StringSplitOptions]::RemoveEmptyEntries)[0]
$actual = (Get-FileHash $installerPath -Algorithm SHA256).Hash

if ($actual -ne $expected) {
    throw "SHA-256 checksum mismatch."
}

"SHA-256 checksum is valid."
```

Замените `1.0.0` на номер скачанной версии.

## Обновление

Пока автоматическое обновление не реализовано.

Чтобы обновить приложение вручную:

1. Закройте все экземпляры SimpleGit11.
2. Скачайте MSI новой версии.
3. При необходимости проверьте SHA-256.
4. Запустите MSI и завершите обновление.
5. Запустите `SimpleGit11.exe`.

Настройки и список недавних репозиториев хранятся отдельно:

```text
%LOCALAPPDATA%\SimpleGit11\settings.json
```

Обновление через MSI сохраняет пользовательские настройки и выбор компонентов.

## Сборка из исходного кода

Клонирование Git-репозитория предпочтительнее скачивания автоматически сформированного архива исходного кода: MinVer использует Git-теги для вычисления версии.

Восстановите зависимости:

```powershell
dotnet restore .\SimpleGit11.slnx
```

Соберите Debug-версию только для `x64`:

```powershell
dotnet build .\SimpleGit11.slnx `
  -c Debug `
  -p:Platform=x64
```

Результат сборки:

```text
SimpleGit11\bin\x64\Debug\net8.0-windows10.0.19041.0\win-x64\
```

Запуск собранного приложения:

```powershell
& ".\SimpleGit11\bin\x64\Debug\net8.0-windows10.0.19041.0\win-x64\SimpleGit11.exe"
```

## Подготовка MSI и SHA-256

Скрипт публикации создаёт только установщики. Он выполняет self-contained
публикацию, собирает лицензии, проверяет WinUI-файлы, затем собирает MSI на
русском и английском. WiX SDK 7 и расширения UI/Util — зависимости сборки.
Перед использованием `-AcceptWixEula` ознакомьтесь с
[условиями WiX](https://docs.firegiant.com/wix/osmf/).

```powershell
# Стабильный релиз
.\Publish-Release.cmd.bat

# Тег preview/rc: числовая версия приложения определяется автоматически
.\Publish-Release.cmd.bat

# Тестовая сборка из любой ветки
.\Publish-Release-dev.cmd.bat
```

Релизный режим требует чистого рабочего дерева, ровно одного тега
`vMAJOR.MINOR.PATCH[-PRERELEASE]` на `HEAD` и совпадения версии EXE с тегом.
Публичный release workflow принимает стабильные теги и каналы `preview.N`,
`rc.N`. Числовые prerelease-идентификаторы не допускают ведущих нулей.

Development-режим допускает незакоммиченные изменения и не требует тега.
Версия приложения имеет вид `<next-patch>-dev.local.<timestamp>`.
MSI автоматически получает числовую часть: `1.0.0-dev.local.20260831...` → `1.0.0`.
Именно этот номер отображается в списке приложений Windows. У stable версии
совпадают полностью; допустимый диапазон MSI — до `255.255.65535`.

Установка другого пакета с тем же номером и понижение версии остаются запрещены.
Для замены тестовой сборки другой сборкой с тем же числовым номером (включая stable)
сначала удалите предыдущую; настройки по умолчанию сохраняются. Для prerelease
при необходимости можно явно передать `-InstallerVersion` с большим номером.
Стабильную версию переопределять нельзя.

Все BAT запускаются без аргументов: они включают `-Interactive` и предлагают
подтвердить условия WiX в консоли. Ответ `y` или `yes` означает согласие для
текущей сборки; Enter или другой ответ отменяет публикацию до сборки и остановки
приложения. Согласие не сохраняется. Для автоматизации PowerShell остаётся
`-AcceptWixEula`; явная передача этого параметра в BAT пропускает вопрос.

Обе BAT-обёртки закрывают запущенный SimpleGit11. Прямой вызов PowerShell
без `-StopRunningApp` вместо этого требует закрыть приложение самостоятельно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\SimpleGit11\Build\Publish-Release.ps1 `
  -DevelopmentBuild -AcceptWixEula
```

В `artifacts` создаются только распространяемые файлы:

```text
SimpleGit11-<version>-win-x64-en-US.msi
SimpleGit11-<version>-win-x64-en-US.msi.sha256
SimpleGit11-<version>-win-x64-ru-RU.msi
SimpleGit11-<version>-win-x64-ru-RU.msi.sha256
```

Каталоги `.publish-staging-win-x64` и `.installer-staging-win-x64` внутри
`artifacts` — внутренние промежуточные данные сборки, не отдельный дистрибутив.
Старые артефакты автоматически не удаляются. Параметр `-Installer` больше не нужен
и удалён: MSI создаётся всегда.

В MSI сохранены `LICENSE`, `THIRD-PARTY-NOTICES.txt` и каталог `Licenses`;
зависимости SSH и их лицензии относятся к необязательному компоненту.
Публикация завершается ошибкой при отсутствии обязательных файлов или лицензий.
Проверяются таблицы MSI, изоляция SSH и условия очистки данных.

Скрипты не создают коммиты и теги, не выполняют push, не создают GitHub Release,
не устанавливают MSI и не запускают приложение. Пакеты пока не подписываются.
Перед публичным распространением подпишите их сертификатом с временной меткой,
проверьте подпись и пересчитайте SHA-256.
Подробности: [руководство установщика](SimpleGit11.Installer/README.md).

## CI и проверка релизного тега

CI собирает Release x64 и запускает тесты всего решения, включая SSH-плагин.
При отправке релизного тега всегда проверяются его формат и принадлежность
коммита ветке `main`. Повторная сборка и тесты пропускаются только при совпадении
точного SHA с последним запуском `ci.yml` после push в `main`, если через API
GitHub подтверждены успешные шаги сборки Release x64 и тестов приложения/SSH.

Прежний успешный результат не заменяет более поздний неуспешный, отменённый
или ещё выполняющийся запуск. Отсутствие результата, пропущенные шаги, неполная
история или ошибка API приводят к обычной повторной сборке и тестированию.
В итогах workflow указывается ссылка на использованную попытку CI либо причина
повторной проверки. Для Actions предоставляется только право чтения.

Сборка MSI и публикация GitHub Release остаются ручными. Тег влияет на версию
MinVer, поэтому повторное использование результата тестов исходного кода
не заменяет локальную сборку и проверку дистрибутива с релизного тега.

## Версионирование

Версия вычисляется пакетом [MinVer](https://github.com/adamralph/minver) из тегов формата:

```text
vMAJOR.MINOR.PATCH[-PRERELEASE]
```

Проект следует [Semantic Versioning 2.0.0](https://semver.org/):

- patch, например `1.0.1`, — исправления;
- minor, например `1.1.0`, — новая обратно совместимая функциональность;
- major, например `2.0.0`, — несовместимые изменения.
- prerelease, например `1.0.0-preview.1`, — предварительная версия, которая предшествует стабильной `1.0.0`.

Сборка коммита, отмеченного тегом `v1.0.0-preview.1`, получает версию
`1.0.0-preview.1`, а тег `v1.0.0` создаёт стабильную версию `1.0.0`.
Нетегированные сборки получают prerelease-версию с информацией о коммите.

## Подпись и предупреждения Windows

Unpackaged-приложение может запускаться без сертификата. Однако неподписанный или недавно опубликованный бинарный файл может вызвать предупреждение Microsoft Defender SmartScreen.

Скачивайте дистрибутив только из официального раздела Releases и проверяйте опубликованный SHA-256.
